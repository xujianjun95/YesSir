# 自定义 AI 分组规则设计

## 目标

允许用户通过“自然语言描述”或“结构化匹配规则”定义长期分类原则，并为分类指定名称、Emoji 和 Chrome 标签组颜色。用户点击“AI 分类”时，系统根据当前时间加载适用规则：结构化规则先确定匹配标签，描述规则和系统默认规则再由 AI 处理剩余标签。

## 首版范围

- 设置菜单新增“自定义规则”。
- 支持规则的新建、编辑、启用、停用、删除和优先级调整。
- 每条规则采用单页编辑器，并通过单选切换“描述”或“自定义规则”模式。
- 规则支持始终生效或按星期、时间段生效。
- 描述模式仅支持自然语言内容。
- 自定义规则模式支持在一条规则内创建多个标签页分组；每个分组拥有自己的样式和多条匹配条件。
- AI 必须优先使用适用规则，但允许为未匹配标签新建其他分类。
- 数据仅保存在 `chrome.storage.local`，不做云同步。

首版不包含规则模板市场、账号同步、导入导出、复杂条件表达式和基于地理位置的调度。

## 用户流程

1. 用户打开标签切换面板的设置菜单。
2. 点击“自定义规则”，进入规则列表。
3. 点击“新建规则”，打开单页编辑器。
4. 填写规则名称，并选择“描述”或“自定义规则”。
5. 描述模式填写自然语言说明；自定义规则模式创建一个或多个标签页分组，并分别配置样式和匹配条件。
6. 选择执行时间。
7. 保存后返回规则列表，可启停或调整优先级。
8. 下次点击“AI 分类”时，系统自动应用当前有效规则。

## 规则编辑器

每条规则包含：

- `name`：必填，规则名称。
- `type`：`description` 或 `matcher`；历史数据缺省时按 `description` 处理。
- `enabled`：是否参与匹配。
- `schedule`：始终生效或定时生效。
- `instructions`：描述模式必填，自然语言分类要求；编辑器下方提供示例提示。
- `groups`：自定义规则模式必填的标签页分组列表。

自定义规则模式的每个标签页分组包含 `id`、`name`、`emoji`、`color` 和 `conditions`。每条匹配条件包含：

- `field`：`domain`（网站域名）、`title`（页面标题）或 `url`（完整网址）。
- `operator`：`contains`（包含）、`equals`（等于）、`startsWith`（开头是）或 `endsWith`（结尾是）。
- `value`：非空匹配值。

匹配统一忽略英文大小写；域名使用 URL 的 `hostname`。同一分组的多条条件为“或”关系，任意一条命中即进入该分组。规则内部的分组按界面从上到下匹配，标签命中第一个分组后停止继续匹配。首版不支持正则表达式。

保存时校验名称、模式对应内容、时间范围和分类字段；阻止空内容、重复分组名称和不支持的颜色值。首版最多保存 20 条规则；单条规则名称最多 40 个字符、自然语言内容最多 2000 个字符、自定义规则模式标签页分组最多 20 个，分类名称最多 30 个字符，每个分组的匹配条件最多 20 条，单个匹配值最多 300 个字符。

## 时间与优先级

规则分为两层：

1. 始终生效规则作为基础规则。
2. 当前本地时间命中的定时规则叠加执行，并拥有更高优先级。

同层规则冲突时，规则列表中更靠上的规则优先。定时规则支持星期选择和跨夜时间段，例如周一至周五 `18:00—次日 09:00`。跨夜规则选择的星期表示开始日，因此“周五 18:00—次日 09:00”覆盖周五晚上至周六早晨。

时间判断使用用户设备本地时区。若没有启用或命中的规则，AI 分类沿用现有默认全局聚类逻辑。

## AI 分类数据流

1. 用户点击“AI 分类”。
2. 后台读取规则列表并按照当前本地时间筛选有效规则。
3. 先执行有效的结构化规则：定时规则高于始终生效规则；同层列表靠上的规则优先；同一规则内部的标签页分组按从上到下执行。一个标签命中首个分组后停止继续匹配。
4. 命中的标签直接得到对应结构化标签页分组，不交给 AI 改写。
5. 按“基础描述规则在前、定时描述规则在后；同层低优先级在前、高优先级在后”的顺序构造提示词。
6. 将剩余 HTTP(S) 标签和有效自然语言描述一次性交给 AI；若没有剩余标签则跳过 AI 请求。
7. AI 返回剩余标签对应的分类标题；未匹配标签允许新建其他分类。
8. 创建 Chrome 标签组时，结构化目标分组使用用户指定颜色；AI 新建分类继续使用现有自动选色策略。
9. 新结果覆盖 AI 分组缓存，保持面板展示与真实 Chrome 标签组一致。

只有用户明确创建的结构化规则可以提前确定分组；描述规则和历史域名偏好不直接硬分配标签，避免重新引入隐式分类锁死问题。

## 存储模型

使用版本化键 `ysCustomGroupingRulesV1`，值为规则数组。每条规则具有稳定 `id` 和显式 `order`，以便后续迁移：

```js
{
  id: "rule-id",
  name: "工作时间分类",
  type: "description",
  instructions: "工作时间优先按任务类型分类……",
  enabled: true,
  order: 0,
  schedule: {
    mode: "weekly",
    days: [1, 2, 3, 4, 5],
    start: "09:00",
    end: "18:00"
  },
  createdAt: 0,
  updatedAt: 0
}
```

结构化规则示例：

```js
{
  id: "rule-news",
  name: "新闻网站",
  type: "matcher",
  enabled: true,
  order: 0,
  schedule: { mode: "always" },
  groups: [
    {
      id: "group-news",
      name: "新闻",
      emoji: "📰",
      color: "blue",
      conditions: [
        { id: "condition-1", field: "domain", operator: "contains", value: "news.qq.com" },
        { id: "condition-2", field: "domain", operator: "contains", value: "news.163.com" }
      ]
    },
    {
      id: "group-shopping",
      name: "购物",
      emoji: "🛍️",
      color: "red",
      conditions: [
        { id: "condition-3", field: "domain", operator: "contains", value: "taobao.com" }
      ]
    }
  ],
  createdAt: 0,
  updatedAt: 0
}
```

`schedule.mode` 支持 `always` 和 `weekly`。星期使用 JavaScript `Date#getDay()` 的 `0—6` 值域。

## 异常与边界

- 存储数据损坏：忽略非法规则，继续使用其余有效规则或默认分组。
- 规则内容过长：编辑器按上述上限阻止保存，后台再次校验并忽略超出上限的部分。
- 多条规则冲突：按时间层级和列表顺序解决，并在提示词中明确优先级。
- 结构化条件无法解析 URL：域名条件视为不匹配，标题和完整网址条件仍可正常判断。
- 自定义规则缺少有效标签页分组时忽略该规则；分组缺少名称、Emoji 或有效条件时忽略该分组，继续执行规则内其他有效分组。
- AI 返回缺失或无法解析：沿用现有错误提示，不创建部分标签组。
- 跨夜时段：开始时间大于结束时间时，匹配“当天开始后”或“次日结束前”。
- 规则编辑重复提交：保存按钮在写入期间禁用，完成后再关闭编辑器。

## 验证

- 单元测试规则时间匹配，包括工作日、周末、边界分钟和跨夜时段。
- 单元测试基础规则与定时规则的排序和冲突优先级。
- 单元测试三个匹配字段、四个判断方式、多条件“或”关系和大小写归一化。
- 单元测试结构化规则冲突时“定时优先、规则列表靠上优先、规则内分组靠上优先、首个命中停止”。
- 回归测试确认 AI 分类发送全部未被结构化规则命中的当前标签，不被旧缓存跳过。
- 回归测试确认结构化规则命中的标签不再交给 AI，剩余标签仍执行全局聚类；全部命中时不调用 AI。
- 测试结构化分组颜色映射，以及 AI 新建分类的自动颜色兜底。
- 手动验证规则列表、单页编辑、启停、排序、空状态、错误状态、中英文和窄屏布局。

## 兼容性

现有规则缺少 `type` 时自动按 `description` 读取，原有自然语言内容、时间和优先级不丢失；旧版描述规则中的固定分类字段停止使用，并在下次保存时清理。已保存的单分组结构化规则会把原 `targetCategory + conditions` 自动迁移为 `groups[0]`。现有 `ysUserTopicPrefs` / `ysUserTopicPrefs_en` 保留，不删除用户数据；自定义规则作为更明确的高优先级输入。未创建自定义规则的用户行为不变。现有 `ai_batch_group` 消息结构保持兼容，由后台自行读取规则存储。
